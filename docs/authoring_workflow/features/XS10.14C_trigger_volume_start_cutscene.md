# XS10.14C — Trigger Volume Start Cutscene

## Context
Trigger volumes already support onEnter scripts. Cutscenes can now be created as canonical level data.

## Goal
Allow designer to launch a cutscene from a trigger volume.

## Scope
- Support `start_cutscene` command referencing canonical cutscene id.
- Ensure trigger/onEnter can execute `start_cutscene` with `cutsceneId`.
- Add demo external trigger script if useful.
- Add validation/diagnostics:
  - missing cutsceneId
  - unknown cutscene id
  - wrong category if applicable
- Trigger inspector should make it clear which script launches cutscene.
- Runtime should not crash if cutscene id missing/invalid.
- If full cutscene director is not ready, trace should clearly say launched/requested/deferred.

## Non-goals
- no cutscene timeline playback
- no Play/Pause/Stop UI
- no NPC takeover
- no camera actor runtime movement
- no browser script editor
- no physics/collision changes

## Acceptance
1. Create cutscene.
2. Create trigger volume.
3. Assign trigger/onEnter script with `start_cutscene` cutsceneId.
4. Enter trigger.
5. Runtime trace shows cutscene start/request for correct id.
6. Missing cutscene id produces diagnostic, not crash.
7. Export/Import preserves trigger script binding and cutscene data.
8. Existing trigger/onEnter behavior remains working.
9. `npm run build-nolog` passes.
10. `npm run validate-authoring` passes.
11. `git diff --name-only -- src/game/authoring/editor_v2` is empty.
