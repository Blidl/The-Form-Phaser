# XS10.13 — NPC Settings, Appearance, and Collision v1

## Source spec
Based on project authoring tool requirements for NPC:
- NPC can be created, selected, dragged, resized/rotated later.
- Bounds/spawn position use center x/y.
- Settings include Type, Collision, Name.
- Type defines external/functional NPC form: ball, triangle, square, rectangle.
- Collision controls whether NPC collides with player or only with world.
- Visual includes shader, texture, fill, stroke.
- Action includes Spawn X/Y, Default Patrol Behavior, Default Action, Alt Actions.
- Save/Undo/Lock/Del/Copy/Paste are required eventually.
- For this XS, implement only the small safe slice below.

## Current accepted state
- NPC create/select/drag/delete works.
- NPC list exists.
- NPC patrol works.
- NPC defaultAction runtime works.
- Legacy autonomous NPC behavior is disabled.
- NPC interactions are scoped per NPC instance.
- File-based scripts and validate-authoring exist.

## Goal
Allow configuring selected NPC instance settings, appearance, render order/layer, and player collision behavior in active NPC inspector.

## User outcome
Designer can create two NPCs and make them visually different:
- npc_1: square, red fill, black stroke, blocks player.
- npc_2: circle/triangle, blue fill, white stroke, non-blocking/overlap if supported.
Settings persist through Save Draft, Export, Import, Reload.

## Scope
Implement per-instance NPC configuration:
- name/displayName
- type/shape: ball/circle, square, triangle, rectangle
- player collision/contact mode using existing field if available
- fill color
- stroke color
- stroke width
- alpha
- scaleX / scaleY or width/height only if safe
- facing
- visualLayer / renderOrder if already compatible with current runtime
- optional textureKey / frame fields only if current runtime can safely apply or fallback

## Suggested config shape
Prefer extending current NPC config minimally.

Use existing fields where already present:
- id
- profileId
- x
- y
- facing
- visualLayer
- renderOrder
- playerBodyContactMode

Add optional per-instance overrides only if not already available:

visualOverrides?: {
  shape?: "circle" | "ball" | "square" | "triangle" | "rectangle";
  textureKey?: string;
  frame?: string;
  fillColor?: string;
  strokeColor?: string;
  strokeWidth?: number;
  alpha?: number;
  scaleX?: number;
  scaleY?: number;
}

Do not add body/hitbox override fields in this XS unless required for existing rendering.

## Inspector behavior
In NPC tab right inspector add/complete sections:

Settings:
- Name
- Type / Shape dropdown
- Player collision/contact dropdown

Visual:
- Fill color
- Stroke color
- Stroke width
- Alpha
- Scale X/Y
- Facing
- Visual layer
- Render order
- Texture key / frame if safe

Actions:
- Keep existing Patrol
- Keep existing Default Action
- Alt Actions may stay deferred/read-only

Changes must affect only selected NPC instance.

## Runtime behavior
- Resolve final visual from profile/defaults + selected NPC instance overrides.
- Apply visual updates live after inspector change.
- Shape is visual in this XS.
- Triangle exact physics is out of scope.
- Collision body may use current Arcade body approximation.
- Player collision/contact setting should use existing runtime semantics.
- Do not break NPC gravity, patrol, defaultAction, or npc/onInteract.
- Do not change trigger/platform/level systems.

## Collision semantics
Use existing NPC field if available, likely playerBodyContactMode.
Map UI to existing allowed values.
If exact yes/no is required:
- Yes/block => player collision enabled.
- No/overlap/none => no blocking collision with player, according to existing runtime support.
Do not invent duplicate collision fields if an existing field already exists.

## Non-goals
- no npc.jump
- no cutscene takeover
- no exact triangle physics
- no body/hitbox editor
- no browser script editor
- no generic ActionCommandRegistry rewrite
- no Copy/Paste/Duplicate/Lock in this XS
- no Background/Object systems changes

## Acceptance
1. Create npc_1 and npc_2.
2. Set npc_1 shape square, fill red, stroke black.
3. Set npc_2 shape circle or triangle, fill blue, stroke white.
4. Visual settings do not bleed between NPC instances.
5. Change alpha/scale/facing and verify live update.
6. Set player collision/contact mode and verify behavior according to existing runtime support.
7. Patrol still works.
8. Default Action still works.
9. npc/onInteract still works.
10. Save Draft → Reload preserves settings.
11. Export JSON contains only canonical NPC config/visualOverrides.
12. Export JSON does not contain runtime/debug/current state.
13. npm run build-nolog passes.
14. npm run validate-authoring passes.
15. git diff --name-only -- src/game/authoring/editor_v2 is empty.
